# openclaw-scribe

Компактное расширение Chrome/Opera и нативный плагин OpenClaw:
**звук выбранной вкладки + микрофон → локальный Whisper → штатные встречи**.
Без отдельного сервера, Docker и UI-фреймворков. Плагин работает внутри
Gateway; архив, поиск, итоги и экспорт предоставляет OpenClaw.

## Подключение

Скачайте два файла из [Releases](https://github.com/Efreh/openclaw-scribe/releases):

- `efreh-openclaw-scribe-<версия>.tgz` — готовый плагин, без установки зависимостей проекта.
- `openclaw-scribe-browser-<версия>.zip` — готовое расширение, `manifest.json` в корне архива.

`SHA256SUMS` содержит контрольные суммы обоих файлов.

### OpenClaw

Проверено с **OpenClaw 2026.10.7**. Требуется поддерживаемый им Node.js
**24.22.1+ (24.x)** либо **26.12.1+**, а также уже настроенный локальный
аудио-CLI в `tools.media.models` (например, whisper.cpp с моделью и FFmpeg).
Scribe не скачивает модели и не подключает облачный ASR: использует только
аудиосовместимые записи `type: cli` из настроек хоста.

```sh
openclaw plugins install npm-pack:/абсолютный/путь/efreh-openclaw-scribe-0.1.0.tgz --accept-capabilities
openclaw scribe setup
openclaw gateway restart
openclaw scribe pair
```

Установка объявляет источник стенограмм и локальные команды `scribe`.
`setup` включает штатное хранение стенограмм и добавляет один источник
`openclaw-scribe` с `whenOccupied: true`, сохраняя остальные источники.
В данном провайдере «занятость» означает нажатие **Начать запись**, а не
появление людей в звонке: при старте Gateway звук не захватывается.

`pair` печатает адрес и отдельный токен для расширения. Токен хранится локально
в `<stateDir>/scribe/pairing-token` с правами `0600`; токен Gateway расширению
не нужен. По умолчанию соединение идёт на `ws://127.0.0.1:19789`.

При необходимости в `plugins.entries.openclaw-scribe.config` задайте `port`
и/или `extensionIds` (список разрешённых ID расширения). Слушатель всегда
привязан к loopback; веб-страницы не допускаются по Origin, расширение
дополнительно проверяется токеном. Отдельного процесса Scribe нет.

### Chrome / Opera

1. Распакуйте ZIP в постоянный каталог.
2. Откройте `chrome://extensions` или `opera://extensions`, включите режим
   разработчика и выберите **Загрузить распакованное расширение**.
3. Откройте popup Scribe и перенесите адрес и токен из `openclaw scribe pair`
   в раздел **Подключение**.
4. Если нужен микрофон, нажмите **Разрешить доступ к микрофону**. Одноразовая
   страница выдачи разрешения не запускает запись; после неё вернитесь во встречу.
5. Выберите микрофон (системный, конкретное устройство или «Без микрофона»),
   откройте нужную веб-вкладку и нажмите **Начать запись**.

Записывается только вкладка, активная в момент старта. Переключение вкладок
не меняет источник; закрытие popup не останавливает запись. В popup видны
название вкладки, отдельные уровни, длительность и последние 100 реплик.
Переключатель текста влияет только на его отображение.

**Остановить** досылает остатки обеих дорожек, ждёт распознавания и сохранения.
Полная стенограмма и итоги доступны во **Встречах** OpenClaw.
Системные страницы браузера не записываются. При потере соединения или
переполнении очереди запись останавливается с явной ошибкой.

## Границы первой версии

- Интерфейс один — стандартный popup, не боковая панель.
- Распознавание идёт фрагментами по 10 секунд, не пословно.
- Метки **Вкладка** и **Микрофон** обозначают раздельные источники, а не
  диаризацию людей. Различение нескольких собеседников внутри вкладки пока
  не реализовано; имена участников не угадываются.
- Сохранение и сводки полностью штатные: OpenClaw может обновлять итоги
  примерно раз в пять минут и делает окончательные после остановки.
  Отдельного режима «модель только в конце» в используемом SDK нет.
- Исходное аудио не архивируется: временные WAV удаляются после обработки,
  долговременно сохраняется стенограмма. Автовосстановления потерянных
  аудиофрагментов после разрыва или перезапуска нет.
- Целевые браузеры — Chromium-совместимые с MV3, offscreen и tabCapture
  (Chrome 116+). Автотесты запускаются в актуальном Chromium; конкретную
  установку Opera нужно проверить отдельно.
- Браузер и Gateway работают на одном компьютере; для удалённого Gateway
  потребуется отдельно настроенный локальный туннель, не публичный WS.

## Разработка

Весь проект и настройки инструментов расположены в `src/`:

```text
.github/workflows/main.yml   # проверки, CI-артефакты и GitHub Release по тегу
src/
├── extension/              # popup, service worker, offscreen, AudioWorklet
├── plugin/                 # источник стенограмм, локальный WS, CLI
├── shared/                 # бинарный протокол и типы
├── spec/
│   ├── unit/
│   ├── integration/
│   ├── browser/
│   └── support/
├── package.json            # единственный источник версии
├── package-lock.json
├── tsconfig.json
└── build.mjs
```

```sh
cd src
npm ci --ignore-scripts
npm run check
npm test
npm run package
npx playwright install chromium
npm run test:browser
```

Сборка: `dist/browser/` и `dist/plugin/`. Установочные файлы: `artifacts/`.
Runtime плагина содержит собранный JavaScript и использует SDK хоста;
зависимости разработки и исходники в архив не входят.

Аппаратная проверка установленного пакета с реальным Whisper запускается
отдельно на **публичном тестовом аудио**:

```sh
npm run test:native -- --audio /путь/к/тестовой-записи.wav
```

Она создаёт временный профиль, устанавливает TGZ, запускает отдельный Gateway,
проверяет распознавание, штатную стенограмму и финальные заметки, затем
останавливает тестовый процесс. Рабочая конфигурация не изменяется; модель
сводок в тестовом профиле намеренно не настроена, используются штатные
эвристические заметки. Локальный профиль с `proof.json` остаётся для проверки.
`OPENCLAW_BIN` позволяет указать путь к CLI.

На push/PR CI проверяет типы, протокол, сервер и настоящее браузерное
аудио с тестовыми устройствами, затем выдаёт два архива и суммы.
Тег `v<версия из src/package.json>` дополнительно публикует GitHub Release.
Npm/ClawHub и магазины браузеров для подключения не требуются.
