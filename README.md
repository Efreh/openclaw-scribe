# openclaw-scribe

Компактное расширение Chrome/Opera и нативный плагин OpenClaw:
**звук выбранной вкладки + микрофон → выбранный локальный ASR → штатные встречи**.
Без отдельного сервера, Docker и UI-фреймворков. Плагин работает внутри
Gateway; архив, поиск, итоги и экспорт предоставляет OpenClaw.

## Подключение

Скачайте два файла из [Releases](https://github.com/Efreh/openclaw-scribe/releases):

- `efreh-openclaw-scribe-<версия>.tgz` — готовый плагин, без установки зависимостей проекта.
- `openclaw-scribe-browser-<версия>.zip` — готовое расширение, `manifest.json` в корне архива.

`SHA256SUMS` содержит контрольные суммы обоих файлов.

### OpenClaw

Проверено с **OpenClaw 2026.10.7**. Требуется поддерживаемый им Node.js
**24.22.1+ (24.x)** либо **26.12.1+**, а также выбранный локальный ASR.
Для режима по умолчанию нужен аудио-CLI в `tools.media.models`
(например, whisper.cpp с моделью и FFmpeg); GigaAM настраивается отдельно.
По умолчанию Scribe использует локальные аудио-CLI хоста. В 0.3.0 также доступны
резидентная GigaAM 600M и универсальный адаптер локального процесса.
Модели автоматически не скачиваются, облачный ASR не подключается.

```sh
openclaw plugins install npm-pack:/абсолютный/путь/efreh-openclaw-scribe-0.3.0.tgz --force --accept-capabilities
openclaw scribe setup
openclaw gateway restart
openclaw scribe pair
```

Установка объявляет источник стенограмм и локальные команды `scribe`.
`setup` включает штатное хранение стенограмм и добавляет один источник
`openclaw-scribe` с `whenOccupied: true`, сохраняя остальные источники.
В данном провайдере «занятость» означает нажатие **Начать запись**, а не
появление людей в звонке: при старте Gateway звук не захватывается.

`pair` печатает адрес и полный отдельный токен для расширения, готовый к копированию.
Этот явный локальный вывод не проходит через журналирование и маскировку `console.log`;
общая защита секретов OpenClaw не меняется. Токен хранится локально
в `<stateDir>/scribe/pairing-token` с правами `0600`; токен Gateway расширению
не нужен. По умолчанию соединение идёт на `ws://127.0.0.1:19789`.

Для обновления уже установленного плагина повторите `plugins install` с новым TGZ
и `--force`, затем `openclaw gateway restart`. Повторный `scribe setup` не нужен;
настройки и токен подключения сохраняются. Расширение 0.1.x продолжит обычную запись;
для переключателя разделения собеседников установите ZIP расширения 0.2.0.
В версии 0.1.0 команда `pair` маскировала токен; до обновления полный токен можно
прочитать из `<stateDir>/scribe/pairing-token` (обычно `~/.openclaw/scribe/pairing-token`).

При необходимости в `plugins.entries.openclaw-scribe.config` задайте `port`
и/или `extensionIds` (список разрешённых ID расширения). Слушатель всегда
привязан к loopback; веб-страницы не допускаются по Origin, расширение
дополнительно проверяется токеном. Отдельного сетевого сервиса Scribe нет; резидентный ASR при необходимости
запускается дочерним процессом плагина.

### Chrome / Opera

1. Распакуйте ZIP в постоянный каталог.
2. Откройте `chrome://extensions` или `opera://extensions`, включите режим
   разработчика и выберите **Загрузить распакованное расширение**.
3. Откройте popup Scribe и перенесите адрес и токен из `openclaw scribe pair`
   в раздел **Подключение**.
4. Если нужен микрофон, нажмите **Разрешить доступ к микрофону**. Одноразовая
   страница выдачи разрешения не запускает запись; после неё вернитесь во встречу.
5. Выберите микрофон (системный, конкретное устройство или «Без микрофона»),
   откройте нужную веб-вкладку и нажмите **Начать запись**.

Записывается только вкладка, активная в момент старта. Переключение вкладок
не меняет источник; закрытие popup не останавливает запись. В popup видны
название вкладки, отдельные уровни, длительность и последние 100 реплик.
Переключатель текста влияет только на его отображение.

**Остановить** досылает остатки обеих дорожек, ждёт распознавания и сохранения.
Полная стенограмма и итоги доступны во **Встречах** OpenClaw.
Системные страницы браузера не записываются. При потере соединения или
переполнении очереди запись останавливается с явной ошибкой.

## Выбор модели распознавания (0.3.0)

См. [контракт ASR и настройку GigaAM](docs/asr.md). По умолчанию совместимость
с настроенным локальным CLI OpenClaw сохраняется. Для GigaAM Multilingual
Large 600M есть готовый адаптер: модель загружается один раз при первом аудио
и повторно используется до остановки сервиса Gateway. Настройки ASR и диаризации
раздельные; расширение менять при смене модели не требуется.

## Разделение собеседников (0.2.0)

Используется готовый локальный движок **[NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp)**
и **[NVIDIA Nemotron 3 Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)**.
Проверенный выпуск CLI — **0.2.0**, одна дополнительная модель — **107 МБ** (Q8_0).
Самому диаризатору аккаунт, регистрация, API-ключ, Python, PyTorch и отдельный сервер не нужны.
Распознавание текста выполняет выбранный ASR независимо от диаризатора.
Команда настройки диаризации не устанавливает ASR-модели. Нейросеть и сопоставление голосов предоставлены NVIDIA,
а не самодельным сравнением отдельных десятисекундных фрагментов.

1. Установите `nemo-speech` по [официальной инструкции](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/v0.2.0/docs/install.md).
   Для GPU нужен соответствующий выпуск CLI; CPU тоже поддерживается.
2. Один раз выполните:

   ```sh
   openclaw scribe setup --diarization
   openclaw gateway restart
   ```

   Команда использует штатный `nemo-speech pull nemotron-diar`: скачивается только
   модель диаризации, с проверкой размера и SHA-256 средствами самого движка.
   Повторные вызовы используют общий кэш `nemo-speech`, без копий весов в плагине.
3. В расширении включите **Разделить собеседников после записи**, затем запишите встречу.

Во время записи показывается живой черновик **Вкладка / Микрофон**. После остановки
движок обрабатывает звук вкладки целиком штатным проходом с сохранением состояния
голосов, затем выбранный ASR распознаёт реплики по найденным границам. В popup виден
этап обработки и прогресс итогового текста. На длинной встрече нужно дождаться
завершения; закрытие popup не прерывает обработку.

В итоговой стенограмме — **Участник 1, Участник 2…**, по порядку появления голоса,
до **8 голосов во вкладке**. Повторные реплики сохраняют номер в пределах встречи.
Микрофон остаётся отдельным источником; несколько людей у одного локального
микрофона этой версией не разделяются. Имена не угадываются, узнавания людей
между разными встречами нет.

Одновременная речь помечается явно: модель определяет активные голоса, но не
разделяет смешанный звук на чистые дорожки. Точность не гарантируется при шуме,
очень коротких репликах, похожих голосах и превышении лимита участников.

При включённом разделении **во Встречи сохраняется только итог**, без дублирования
живого черновика: штатное хранилище OpenClaw добавляет реплики, но не заменяет их.
Звук вкладки и резервный текст временно хранятся в `<stateDir>/scribe/work/recording-*`
с правами `0700` на каталог и `0600` на файлы. После успешного сохранения они удаляются.
Лимит одной записи — 4 часа. Если диаризация не завершилась, сохраняется черновик
без разделения и показывается предупреждение; временный WAV и журнал остаются
по указанному пути для восстановления. После аварийного завершения Gateway
они также могут остаться; автоматического восстановления в этой версии нет.
Обычный режим без разделения работает как прежде и не хранит полную запись.

Проверки: публичные примеры с 2 и 4 голосами, включая повторное появление одного
говорящего, без ручной настройки числа участников; CPU/CUDA, реальный браузер,
ошибка модели и сохранение резервного текста. Это проверки интеграции, не гарантия
качества для любого звонка. См. [проверку движка](src/spec/integration/diarization-native.spec.ts).

## Возможности и ограничения

- Интерфейс один — стандартный popup, не боковая панель.
- Распознавание идёт фрагментами по 10 секунд, не пословно.
- Без включённого разделения метки **Вкладка** и **Микрофон** обозначают
  источники, не отдельных людей. Диаризация включается отдельно, как описано выше.
- Сохранение и сводки полностью штатные: OpenClaw может обновлять итоги
  примерно раз в пять минут и делает окончательные после остановки.
  В режиме диаризации реплики поступают в штатное хранилище только после остановки,
  поэтому содержательные итоги также появляются после финальной обработки.
- Исходное аудио не архивируется после успешной обработки. В режиме диаризации
  временная полная запись нужна до сохранения результата; при ошибке сохраняется
  для восстановления. Автовосстановления потерянных аудиофрагментов нет.
- Целевые браузеры — Chromium-совместимые с MV3, offscreen и tabCapture
  (Chrome 116+). Автотесты запускаются в актуальном Chromium; конкретную
  установку Opera нужно проверить отдельно.
- Браузер и Gateway работают на одном компьютере; для удалённого Gateway
  потребуется отдельно настроенный локальный туннель, не публичный WS.

## Разработка

Весь проект и настройки инструментов расположены в `src/`:

```text
.github/workflows/main.yml   # проверки, CI-артефакты и GitHub Release по тегу
src/
├── extension/              # popup, service worker, offscreen, AudioWorklet
├── plugin/                 # источник стенограмм, локальный WS, CLI
├── shared/                 # бинарный протокол и типы
├── spec/
│   ├── unit/
│   ├── integration/
│   ├── browser/
│   └── support/
├── package.json            # единственный источник версии
├── package-lock.json
├── tsconfig.json
└── build.mjs
```

```sh
cd src
npm ci --ignore-scripts
npm run check
npm test
npm run package
npm run test:pair
npx playwright install chromium
npm run test:browser
```

Проверка настоящей модели требует установленного `nemo-speech` (модель скачивается
штатным CLI без регистрации, аудио не загружается в сеть):

```sh
npm run test:diarization
# Для явного CUDA-прогона:
NEMO_DEVICE=cuda:0 npm run test:diarization
```

Сборка: `dist/browser/` и `dist/plugin/`. Установочные файлы: `artifacts/`.
Runtime плагина содержит собранный JavaScript, Python-адаптер GigaAM и использует SDK хоста;
зависимости разработки и исходники в архив не входят.

Аппаратная проверка установленного пакета с реальным Whisper запускается
отдельно на **публичном тестовом аудио**:

```sh
npm run test:native -- --audio /путь/к/тестовой-записи.wav
# Полный путь с диаризацией и реальным Whisper на двухголосном публичном примере:
npm run test:native -- --audio /путь/к/sample.wav --language en --duration 30 --diarization
```

Она создаёт временный профиль, устанавливает TGZ, запускает отдельный Gateway,
проверяет распознавание, штатную стенограмму и финальные заметки, затем
останавливает тестовый процесс. Рабочая конфигурация не изменяется; модель
сводок в тестовом профиле намеренно не настроена, используются штатные
эвристические заметки. Локальный профиль с `proof.json` остаётся для проверки.
`OPENCLAW_BIN` позволяет указать путь к CLI.

`test:pair` устанавливает собранный TGZ в отдельный временный профиль и проверяет
полный токен в выводе настоящего CLI, повторное использование токена, настроенный
порт и отсутствие токена в журнале. Рабочий Gateway не запускается и не меняется.

На push/PR CI проверяет типы, протокол, сервер, команду подключения,
настоящую модель диаризации на размеченном публичном аудио и настоящее браузерное
аудио с тестовыми устройствами, затем выдаёт два архива и суммы.
Тег `v<версия из src/package.json>` дополнительно публикует GitHub Release.
Npm/ClawHub и магазины браузеров для подключения не требуются.
